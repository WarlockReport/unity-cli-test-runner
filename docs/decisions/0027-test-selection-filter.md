# ADR-0027: 除く名前・カテゴリによる絞り込み実行を、Unity の Filter の除外指定で 1 回の実行として行う

## Status

Accepted (2026-11-03)

## Context

利用側のプロジェクトから、テストの全件実行に時間とトークンがかかりすぎるという報告があった。PlayMode の 1 アセンブリ
853 件のうち、prefab を組んで演出を実時間で流し切る 6 クラス 88 件が実行時間の 96% を占めていた。利用側は、速いテストを
毎回流し、遅いクラスは変更が影響するものだけを流したい。要望は 2 つあった。

- 案1: アセンブリと除くクラスの完全名を受け取り、残りを流す
- 案2: カテゴリによる絞り込み（含める・除く）をバッチ実行で使えるようにする

テストから一部を除くこと、カテゴリで絞ることは、テストが増えて遅いテストが混ざったプロジェクトならどこでも必要になる。
そのため 2 案を「どちらかを選ぶ候補」ではなく、別の使い道を持つ汎用機能として両方入れることにした
（除外はテストコードに手を入れずに使え、カテゴリはテスト側の分類で指せる）。

既存の手段では表せなかった:

- `--filter_type testName` / `assembly` は部分一致で、別クラス・別アセンブリを巻き込む
- `--filter_type category` は含めるカテゴリを 1 つしか指定できない（除外・複数・アセンブリとの組み合わせ不可）
- 完全名一覧のバッチ実行（`run_tests_batch_*`）で「残り」を表すと、数百件の完全名をコマンド行に載せることになり、
  トークン節約という目的に反する

### 調査（Unity Test Framework 1.6.0 のソース）

- `Filter` の `testNames`・`groupNames`・`assemblyNames`・`categoryNames` の各配列は、先頭が `!` の要素を除外
  （`NotFilter`）として扱う。同じ配列内で含める要素は OR、除く要素は AND で結合され、配列どうしは AND
- `testNames` は完全一致（`FullNameFilter`、非正規表現）。`assemblyNames` は大文字小文字を区別しない完全一致
- `categoryNames` は `CategoryFilterExtended { IsRegex = true }` で、**正規表現の部分一致**
- テストのカテゴリは `GetAllCategoriesFromTest` で親（クラス等）から引き継がれる

### 実測（TestProject、Unity 6000.3.25f1 + `com.unity.pipeline` 0.9.1-exp.1、2026-11-03）

- `testNames` に `!<クラスの完全名>` を入れると、そのクラスの配下がすべて除かれ、名前の先頭が同じ別クラスは残る
- 引数付きメソッドの完全名で除くと、全ケースが除かれる
- 除く要素だけの `testNames`（アセンブリ指定なし）は「それ以外すべて」になる
- 名前空間の完全名で除くと、その配下がすべて除かれる
- `^Slow$` の形にしたカテゴリは、クラスに付けた `[Category("Slow")]` の配下に当たり、`SlowView` には当たらない。
  `slow` では当たらない（大文字小文字を区別する）
- `assemblyNames` に小文字で書いたアセンブリ名でも当たる
- `test list` の `Categories` には、クラスに付けたカテゴリが配下の各メソッドに現れる
- `--filter_type category ExpectedFailure` と `expectedfailure` はどちらも 1 件を実行した（Pipeline 側は
  大文字小文字を区別しない完全一致）
- `unity cmd` に未知の引数を渡すと `INVALID_COMMAND_ARGS` で失敗し、黙って無視されない

## Decision

- Unity 側に新しいコマンド `wr.testrunner run_tests_filtered_editmode` / `run_tests_filtered_playmode` を足す。
  引数は `assembly`・`include_categories`・`exclude_categories`・`exclude_names`（PlayMode は `async_tests` も）。
  これらを `Filter` に直接詰める:
  - `assemblyNames = [assembly]`
  - `categoryNames` = 含める `^<エスケープした名前>$` ＋ 除く `!^<エスケープした名前>$`（正規表現の部分一致を完全一致に包む）
  - `testNames` = 除く `!<完全名>`
- 案1・案2 を 1 組のコマンドで実装し、1 回の呼び出しで組み合わせられるようにする。遅いクラスの一部だけを流す集合も、
  流したいクラスを除く名前に入れないことで 1 回で表せる
- 既存コマンドに引数を足さず、新しいコマンド名にする。古い UPM パッケージに新しいプラグインを組み合わせたとき、既存の
  「コマンドが見つからない → 終了コード 3（版ずれ）」の経路に乗せるため。既存コマンドの引数・挙動は変えない
- スクリプト `run-tests-filtered-editmode.sh` / `run-tests-filtered-playmode.sh` は名前付き引数
  （`--assembly`・`--exclude`・`--include-category`・`--exclude-category`）を受け取る
- 綴りの誤りを黙って通さないため、スクリプトは実行前に `test list` で名前の実在を確かめ、1 つでも見つからなければ
  実行せずに終了コード 1 で止める。照合の規則は Unity 側に合わせる（アセンブリは大文字小文字を区別しない完全一致、
  カテゴリは区別する完全一致、除く名前は `FullName` と完全一致するか、直後が `.` か `(` で続くテストがあること。
  `(` を認めるのは、`test list` が引数付きケースを `Method(1,2)` の名前で返すため）。確認をスクリプトに置くのは、
  `test list` の応答だけで判定でき、モック CLI で回帰テストできるため
- PlayMode は既存のバッチ実行の仕組み（リクエスト／ステータスファイル、リロード後の再登録、`batch_test_status`）を共有する。
  除外で絞り込む実行では「指定した名前が結果に含まれるか」を整合性の手がかりにできないため、実行ごとに `requestId` を発行し、
  リクエストファイルに保存してドメインリロードを越えて持ち回り、完了ステータスに載せる。スクリプトは起動応答の
  `RequestId` と照合し、一致しなければ stale として終了コード 3 にする
- 組み合わせの結果が 0 件のときは終了コード 0 のまま、標準エラーで 0 件であることを明示する

### 検討して採らなかった案

- **スクリプトで `test list` から残りの完全名一覧を組み、既存のバッチ実行に渡す**: Unity 側の変更が要らないが、
  コマンド行が数百件になり、利用側のトークン節約という目的に反する
- **既存の `run_tests_batch_*` に任意引数を足す**: 古い UPM パッケージは未知の引数をエラーにするので黙って無視はされないが、
  エラーの形が「コマンドが見つからない」と異なり、版ずれの診断経路に乗らない
- **カテゴリの照合を大文字小文字を区別しない形にする**: `Filter.categoryNames` の正規表現に大文字小文字を無視する指定を
  付けられない（`(?i)` を埋め込む手はあるが、Unity 側の照合の仕様に依存を増やす）。区別する仕様をそのまま文書化した

## Consequences

- アセンブリから遅いクラスを除いた集合、カテゴリで含める・除く集合を、短い 1 回の呼び出しで完全一致で実行できる
- `--filter_type category`（大文字小文字を区別しない）と絞り込み実行のカテゴリ（区別する）で照合の規則が異なる。
  SKILL.md の既知の罠に書いた
- 除く名前に括弧を含む名前は指定できない（既存のバッチ実行と同じ理由で拒否する）。引数付きのケースを 1 件だけ除くことや、
  クラス側に引数がある `[TestFixture(...)]` のクラスを名前で除くことはできない
- 固定台に `CategorizedFixture`（クラスに `Slow`）・`CategoryPrefixFixture`（メソッドに `SlowView`）・
  `CategorizedPlayModeFixture`（クラスに `Slow`）を追加し、`e2e/run-all.sh` に絞り込み実行の段階（段階 9）を加えた。
  EditMode アセンブリ全件の期待値は 14 件から 17 件になった
- 版は 0.9.2（プラグイン・UPM パッケージとも）
